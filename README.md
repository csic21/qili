# 栖理 Qili

一个独立开发的原生 Mac 空间与维护工作台。采用侧栏导航、分类清单和任务面板，
把文件占用、应用管理与日常维护放在同一处。支持 macOS 14 及以上。

## 当前功能

| 工具 | 已实现 | 边界 |
| --- | --- | --- |
| 空间整理 | 用户缓存、日志、Xcode DerivedData、设备支持与 npm 缓存扫描；分类与逐项勾选、路径明细、固定确认栏、停止扫描、清理过程计数进度、确认后可选择移到废纸篓或直接删除 | 路径白名单与符号链接检查；直接删除需勾选「无法从废纸篓恢复」后才会执行；应用自身不清空废纸篓 |
| 应用管理 | 本机应用、图标、版本与大小；搜索、大小排序、按需加载关联文件；逐项勾选卸载并移到废纸篓；Sparkle / Homebrew 更新检查、停止检查与来源级失败详情；用户级启动项启停及真实运行状态 | 应用数据需额外确认；系统后台项只读，不处理共享群组容器、钥匙串及云端数据 |
| 系统维护 | Quick Look 重建、DNS 刷新、Spotlight 索引检查、磁盘校验；按需选择或单独运行、停止后续任务、运行中实时输出、展开执行记录 | 需要权限时由系统授权；索引与磁盘检查只读 |
| 文件地图 | 文件夹选择、逐层测量、占比分布、卡片/列表、搜索、短期返回缓存；在访达中显示 | 此页不执行删除 |
| 运行状态 | CPU / GPU / 内存 / 磁盘 / 网络 / 负载 / 电池及内存占用较高的进程 | 仅前台采样，硬件读取在后台线程；温度、风扇和电池指标随机型可用，无法读取时明确标注 |

扫描与维护通过本机系统接口和命令完成。应用内自动更新通过本仓库 GitHub Releases
上的 Sparkle appcast 完成;应用更新检查还会访问相应更新来源。没有把本机文件内容
上传到服务端的功能。界面支持浅色、深色与跟随系统三种外观,侧栏底部可切换。

## 开发与打包

```bash
swift run
bash scripts/package_app.sh 0.6.0              # dist/Qili.app 与 dist/Qili-0.6.0.dmg
bash scripts/package_app.sh 0.6.0 .build/qili-preview
```

也可用 Xcode 打开 `Package.swift`。内部 SwiftPM 目标与 bundle identifier 仍叫 `MoleApp` /
`com.csic21.moleapp` 以兼容已有构建与更新检查；产品显示名和发行包使用栖理 / Qili。仓库地址为
`csic21/qili`，旧地址 `csic21/mole-app-native` 由 GitHub 自动重定向，旧版本内置的更新源不受影响。

发行包是 DMG:打开后把 `Qili.app` 拖入「应用程序」即可。应用内嵌 Sparkle,首次安装后
会自动检查并直接安装后续版本。当前使用 ad-hoc 签名,尚未完成公证,首次打开需要右键
选择「打开」。

## 验证与扫描基准

```bash
swift test
swiftc -O Sources/MoleApp/FileSizer.swift scripts/scan_benchmark.swift -o /tmp/qili-scan-benchmark
/tmp/qili-scan-benchmark                       # 自动生成并移除 1 万文件的临时测试集
/tmp/qili-scan-benchmark /path/to/directory    # 只读测量指定目录
```

扫描内核使用系统 FTS 物理遍历，不跟随符号链接、不改变工作目录，并逐项检查任务取消。
大小按文件数据分配块计算，权限失败显示不完整结果。资源叉/扩展属性可能造成与 Foundation
资源属性统计的差异；APFS 克隆、硬链接也不等于可独占释放的空间。移到废纸篓后仍占用磁盘空间，
直到在访达中清倒废纸篓；直接删除立即释放空间，但无法从废纸篓恢复。

2026-10-11 本机暖缓存测试（100 目录、10,000 文件，5 次中位数）：Foundation 48 ms，
FTS 15 ms，约 3.3 倍，均统计到 40,960,000 字节。这是扫描内核的测试结果，
不是整机清理或冷缓存扫描的提速承诺。目录返回缓存最多保留 12 个目录、有效期两分钟，
手动重新测量始终绕过缓存。

回归覆盖普通文件、隐藏项、符号链接、稀疏文件、取消扫描、逐项选择、清理路径重校验、
移到废纸篓与直接删除的结果文案、清理过程初始进度、目录返回缓存、命令大量双路输出/超时/取消
及网络计数重置。新增覆盖派生进程清理、
持续输出、首尾日志保留、检查失败与重试、Sparkle 构建号/显示版本和登录项 PID 状态。
测试不清理真实用户文件，也不更新实际软件或启停真实登录项。

应用卸载入口位于「应用管理 → 应用清单 → 展开应用 → 卸载…」。先查看清单，勾选要移走的
关联文件，确认后正常退出应用并移到废纸篓；不会强制结束进程或永久删除。用户缓存、
偏好设置、窗口状态及按应用标识匹配的日志默认选中，应用支持、沙盒容器和仅名称匹配的
目录默认保留，选中数据目录还需额外确认。用户 LaunchAgent 仅在程序路径位于该应用内时
纳入处理，移动前先停止；系统后台项只读。检测到相同标识的应用副本时保留关联文件。
卸载前及逐项执行时重查路径、符号链接与文件身份；应用本体移动失败时保留数据。
结果逐项显示移动、失败和保留，并复查已知路径；不声称能清除所有位置的残留。
卸载测试使用临时目录和模拟废纸篓，不调用真实卸载或 launchctl 修改。

命令通过独立进程组启动,stdout/stderr 持续读取,每个流最多保留 1 MiB,超出时保留首尾
并标注截断,不写临时日志文件。取消或超时先发送 TERM,再清理同组中仍在运行的进程;
已完成的外部修改不会自动回滚,通过系统服务或授权代理启动的独立任务不属于该进程组。
维护页"停止后续任务"仍会等待当前任务结束。更新检查区分成功、失败、取消和无可检查
来源;失败或取消不会阻止立即重试,Homebrew 输出失败或截断不再被当作"没有更新"。

## 品牌素材

透明背景的 1024px 母版：`Assets/Branding/QiliLogo.png`。
鼹鼠图形由内置 image_gen 生成，未输入原版 Logo 作为参考；原始提示词保留在同目录。

```bash
bash scripts/generate_icons.sh
```

该脚本生成多尺寸 `AppIcon.icns`、SwiftPM 图片资源，以及网站 Logo 与 favicon。
打包脚本会把 SwiftPM 资源包复制进 `.app`，开发运行与发行包共用同一套素材。

## 网站

`site/` 是 React + Vite 的产品介绍页，采用独立设计的工作台示意和五项功能说明。
网页数据明确标为示例，不在浏览器中执行本机扫描或清理。

```bash
cd site
pnpm install --frozen-lockfile
pnpm dev
PAGES_BASE=/qili/ pnpm build
```

Pages 工作流仍使用现有仓库路径。下载与源码链接均指向本项目。
